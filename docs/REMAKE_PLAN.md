# LaLa 全新重製規劃（Android 版）

> 狀態：規劃階段；本文件不代表已開始實作、功能已完成或通過真機測試。
> 基準：main 的 v0.0.8。舊版僅作為功能行為、協定與資源來源的參考，不直接沿用舊 UI／架構作為新產品骨架。

## 1. 重製目標

- 從頭建立全新 Android LaLa，與桌面版同步規劃，但保留 Android 原生生命週期與互動設計。
- 使用深藍科技風格，針對手機觸控、單手操作、不同螢幕尺寸及系統主題設計。
- 優先重建 Battle（戰鬥）與 Map（地圖）。
- 保留已驗證的協定、安全檢查與伺服器確認原則；不得把舊版存在的功能直接視為已通過正式服驗收。
- 新舊版分離開發；未經驗證不得覆蓋既有 APK、簽章或發布流程。

## 2. 舊版盤點

逐項記錄：
1. Android 專屬 UI、觸控流程、權限與生命週期。
2. 前景服務、常駐通知、懸浮小球及背景連線的啟停條件。
3. 與桌面版共用的協定模型、封包處理、領域規則與測試。
4. 帳號／伺服器設定隔離、Keystore 使用方式及敏感資料生命週期。
5. 斷線、程序被終止、網路切換、鎖屏及權限撤銷後的恢復行為。
6. 現有自動化測試、APK 建置、簽章與真機驗收紀錄。

## 3. 目標架構（提案）

- **Android UI**：頁面、觸控操作、狀態呈現與無障礙支援。
- **Application／Domain**：戰鬥、地圖及其他功能用例與領域模型。
- **Shared core**：與桌面版共用的協定、資料模型、驗證規則與平台無關測試；共用範圍須以實際依賴盤點確認。
- **Android platform**：前景服務、通知、權限、Keystore、生命週期及平台整合。
- **Infrastructure**：連線、封包、資源載入、日誌及持久化。

Android UI 不應直接操作封包或繞過共用驗證邏輯。最終語言與 UI toolkit 在盤點現有建置、依賴與團隊維護成本後決定。

## 4. 分階段交付

### Phase 0 — 盤點與規格
- 建立功能矩陣、Android 專屬能力清單、共用核心候選清單與測試缺口。
- 定義支援的 Android 版本、ABI、權限與背景執行限制。
- 交付：架構決策紀錄、Battle／Map 驗收案例、真機測試矩陣。

### Phase 1 — 新專案骨架與設計系統
- 建立全新 application ID／入口與建置設定；正式套件識別、簽章及發布策略需另行確認。
- 定義深藍科技風元件、手機導航、載入／空白／錯誤狀態與字體縮放。
- 建立安全的設定儲存與連線狀態基礎。
- 驗收：乾淨環境可建置安裝；權限拒絕與斷線時 UI 不當機。

### Phase 2 — Battle 戰鬥模組（優先）
- 先完成共用戰鬥狀態模型與協定測試，再建置觸控 UI。
- 顯示角色／夥伴狀態、隊伍與陣形、目標、技能／普攻及戰鬥紀錄。
- 自動操作具備明確啟停、狀態回饋、伺服器確認與失敗保護。
- 驗收：單元／整合測試、旋轉與重建狀態測試、網路中斷與真機手動操作。

### Phase 3 — Map 地圖模組
- 建立可觸控地圖、座標與場景狀態、移動控制、路徑／傳點資料及同步服務。
- 針對小螢幕設計縮放、拖曳、控制區與文字可讀性。
- 未驗證傳點或資料不可標示為可用。
- 驗收：座標同步、場景切換、觸控邊界、移動取消、背景／前景切換與斷線復原。

### Phase 4 — 其他功能逐步移植
- 依盤點結果安排帳號／角色、背包、技能、夥伴、社交、紀錄與其他模組。
- 每個模組獨立交付，並檢查帳號／伺服器資料隔離及 Android 生命週期。
- 未驗證的功能明確標示，不以畫面完成代替功能完成。

### Phase 5 — 整合、真機回歸與發佈候選版
- 執行 Android 單元／整合測試、APK 建置、安全掃描及真機驗收。
- 覆蓋支援 Android 版本、ABI、權限撤銷、鎖屏、網路切換及程序回收等情境。
- 驗證 APK 簽章、SHA256、版本資訊與可重現建置。
- 未通過必要驗收前，不建立正式 Release／Tag 或替換正式安裝包。

## 5. 品質與安全門檻

- 帳密與 Token 使用 Android Keystore 保護；不寫入 Log、硬編碼或明文備份。
- 背景連線須符合 Android 前景服務、通知與權限規範；權限失效時提供清楚的復原引導。
- 不把本機 UI 狀態當成伺服器成功執行的證據。
- 官方資源與版本須驗證來源、格式及完整性。
- 明確區分模擬測試、CI、APK 安裝測試與正式服真機 E2E。
- 不為重製而移除既有安全檢查或放寬未驗證操作。

## 6. 目前尚待確認／驗證

- 新版 application ID、簽章沿用或分離策略與正式發布方式。
- Android 最低支援版本、裝置覆蓋範圍及 UI 技術棧。
- Battle、Map 正式服真機驗收證據與可共用核心的邊界。
- 新舊版並行測試、設定遷移與資料相容策略。
